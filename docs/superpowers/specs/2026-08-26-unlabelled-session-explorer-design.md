# 정답 없는 실제 세션 탐색기 — 설계

**상태:** 승인됨 (2026-08-26)
**선행 스펙:** `2026-08-25-audio-segmentation-poc-design.md`
**전제:** 선행 스펙의 파이프라인(어댑터 7종, 캐시, 후처리, 채점 리포트)은 구현·검증 완료

---

## 1. 목적

실제 합주 녹음에 7개 모델을 돌리고, **정답 라벨 없이** 사람이 오디오를 들으며
결과를 눈으로 비교해 모델과 커트라인을 고른다.

### 왜 필요한가

선행 스펙은 유튜브 클립을 레시피대로 조립한 **합성 씬**으로 모델을 채점한다.
정답이 조립 시점에 확정되므로 수동 라벨링이 없다는 게 그 설계의 핵심이었다.
실제로 돌려보니 두 가지가 드러났다:

1. **재료 품질.** 검색 쿼리로 모은 클립이 풀 의도와 맞지 않는 게 많다. 사람이
   전부 듣고 걸러야 하는데, 그 비용이 애초에 피하려던 라벨링 비용에 근접한다.
2. **합성의 구조적 한계.** 블록마다 다른 영상이라 경계에서 방·마이크·음압이
   통째로 바뀐다. 모델이 음악 판별이 아니라 **장면 전환 감지**만으로 점수를 딸
   수 있다. 실제 합주 녹음은 한 방 한 마이크라 그 단서가 없다.

실제 세션을 통째로 쓰면 둘 다 사라진다. 대신 정답이 없어진다. 이 스펙은 정답
없이도 모델을 고를 수 있게 하는 도구를 정의한다.

### 무엇을 포기하는가 (명시)

정답이 없으므로 **자동 채점이 불가능하다.** Music Recall, False Music, 경계
오차, Take 개수 오차 — 전부 계산되지 않는다. 최적 파라미터를 탐색하는
`run_sweep`/`best_point`도 쓸 수 없다. 판단은 전적으로 사람이 한다.

이건 손실이지만 의도된 교환이다. 정량 비교가 필요해지면 세션 몇 개에 라벨을
찍어 기존 채점 리포트를 쓰면 된다 — 그 경로는 그대로 남긴다.

---

## 2. 핵심 결정 — 라벨을 선택사항으로

`data/scenes/`에 wav만 있으면 세션, `.labels.json`이 같이 있으면 채점 가능한
씬으로 취급한다. 둘이 한 디렉터리에 공존한다.

```
data/scenes/session_01.wav              → 탐색 리포트
data/scenes/clean_basic.wav
data/scenes/clean_basic.labels.json     → 기존 채점 리포트
```

별도 명령 계열이나 별도 디렉터리를 만들지 않는 이유: detector 레지스트리,
점수 캐시, RTF/메모리 계측이 전부 재사용된다. 두 벌로 나누면 그 세 가지를
이중 유지하게 된다.

`cmd_run`이 `*.labels.json`을 스캔하는 부분만 `*.wav` 기준으로 바꾸면 세션이
그대로 흘러간다. `cmd_report`는 라벨 있는 씬만 골라 채점하고 나머지는 건너뛴다.

## 3. 구성 요소

### 3.1 세션 수집 — `bandpoc add-session <URL 또는 경로>`

기존 `fetch`는 30초 클립 공장이라 여기 쓸 수 없다. 통짜 녹음을 그대로 가져온다.

- **유튜브 URL** — `python -m yt_dlp`로 wav 추출. 자르지 않는다. 길이 제한 없음.
- **로컬 파일** — `load_audio`로 읽어 작업 샘플레이트(48kHz 모노)로 변환.

산출: `data/scenes/<id>.wav`. 이미 있으면 덮어쓰지 않고 거부한다 — 캐시가
`id`에 묶여 있어 조용히 갈아치우면 옛 점수 곡선이 새 오디오에 붙는다.

**`id` 규칙.** `--id`로 명시할 수 있고, 없으면 유도한다: 유튜브는 video id,
로컬 파일은 확장자 없는 파일명.

파일명과 명시한 `--id`는 slug로 정규화한다 — `[a-z0-9_-]` 밖의 문자는 `_`로,
연속된 `_`는 하나로, 소문자로. 한글·공백·괄호가 든 파일명이 그대로 경로와
캐시 키에 들어가지 않게 하는 게 목적이다. 정규화 결과가 비면 거부하고 `--id`를
요구한다 — `--id`로 준 값이 비어도 마찬가지다.

**유튜브 video id는 예외로 그대로 쓴다** (`igMctbh0pT8`). 대소문자를 뭉개면
세션 id에서 원본 영상을 역추적할 수 없고, 대문자는 경로에도 캐시 키에도
위험하지 않다 — 이 불변식이 막으려는 건 경로 구분자와 비-ASCII다. 다만 URL에서
id를 뽑을 때 쿼리 문자열과 끝 슬래시는 반드시 떨어내야 한다. `youtu.be/<id>/`가
`<id>/`를 남기면 그게 경로 구분자로 해석돼 파일 대신 디렉터리가 생긴다.

라우드니스 정규화는 **하지 않는다.** 합성 씬은 블록마다 정규화하지만, 실제
세션의 음량 변화는 모델이 실제로 마주할 신호의 일부다.

### 3.2 자동 커트라인 — `bandpoc.autothresh`

```python
def auto_threshold(scores: np.ndarray) -> tuple[float, str]:
    """(커트라인, 근거) 반환."""
```

Otsu 방식: 점수 히스토그램을 두 클래스로 나눴을 때 클래스 간 분산이 최대가
되는 지점. 정답 없이 계산되고, 모델별 점수 눈금 차이를 흡수한다.

**단봉 분포 폴백.** 분포가 한 덩어리면 — 모델이 녹음 전체를 음악이라고 하거나
전부 아니라고 한다는 뜻 — Otsu 값은 무의미하다. 클래스 간 분산이 임계 이하면
0.5로 물러나고 근거 문자열에 그 사실을 남긴다. 리포트가 이걸 표시한다.
**모델이 신호를 전혀 분리하지 못한다는 것도 결과다.**

이진 곡선(`ina_segmenter`, `silero_vad`)은 0과 1만 있으므로 Otsu가 자명하게
0.5 근처를 준다. 정상 동작이며, 이 두 모델은 커트라인 조절이 의미 없다는
기존 경고를 리포트에 유지한다.

### 3.3 탐색 리포트 — `bandpoc explore`

**출력 구조.** 세션 수와 무관하게 항상 같은 모양이다 — 세션이 하나뿐일 때만
다르게 동작하면 예측하기 어려워진다.

```
reports/explore/<timestamp>/
  index.html          세션 목록. 각 세션의 길이·모델 수·링크
  <id>.html           세션 페이지 (아래 레이아웃)
  <id>.mp3            그 세션의 오디오
```

**레이아웃** (`<id>.html` 하나당 세션 하나)

```
┌──────────────────────────────────────────────┐
│ ▶ ━━━━━━━━━━●━━━━━━━━━━━━━━  12:34 / 47:20  │  오디오 플레이어
├──────────────────────────────────────────────┤
│ panns_cnn14:music_group      [0.72] ──○───   │  모델명 + 커트라인 슬라이더
│  ▁▃█████▂▁▁▁▂████▇▃▁▁▁▁▁▅███████▃▁           │  점수 곡선
│  ▓▓▓▓▓▓▓▓        ▓▓▓▓▓▓      ▓▓▓▓▓▓▓▓        │  검출 구간
│  3 takes · 3:25-8:10 · 15:20-20:05 · ...     │  구간 목록 (mm:ss)
├──────────────────────────────────────────────┤
│ ast:music_group              [0.55] ─○────   │
└──────────────────────────────────────────────┘
```

**상호작용**

- 타임라인 클릭 → 그 시각부터 재생
- 재생 위치를 모든 모델 행에 세로선으로 표시
- 커트라인 슬라이더 → 구간·개수·목록 즉시 재계산 (서버 없음)
- `min_duration` / `merge_gap` 전역 입력 (기본값은 스펙 § 5의 20s / 10s)

**모델 정렬** — 초기 커트라인에서의 Take 개수 오름차순으로 **고정**한다.
과검출하는 모델이 아래로 가서 눈에 띈다. 슬라이더를 밀어도 순서는 바뀌지
않는다 — 비교하던 행이 눈앞에서 이동하면 읽을 수가 없다.

### 3.4 오디오 전달

**자체 완결 HTML을 포기한다.** 47분 녹음의 mp3가 50MB 남짓인데 data URI로
넣으면 브라우저가 파싱에서 무너진다. 리포트 폴더에 mp3를 나란히 두고
`<audio src="session_01.mp3">`로 참조한다. 로컬 파일 열기로 동작하고 폴더째
옮겨도 깨지지 않는다.

인코딩은 ffmpeg(이미 필수 의존성) 128kbps 모노. 결과는 `data/scenes/<id>.mp3`에
캐시하고 리포트 폴더로 복사한다. 리포트 폴더는 실행마다 새 timestamp로 생기므로,
캐시를 세션 옆에 두지 않으면 `explore`를 돌릴 때마다 47분짜리를 다시 인코딩하게
된다. wav가 mp3보다 새로우면 다시 인코딩한다.

점수 곡선은 7개 모델 합쳐 1MB 남짓이라 HTML 안에 JSON으로 넣는다.

## 4. 데이터 흐름

```
wav ─ detector ─→ 점수곡선 ─ cache(.npz) ─→ 평가격자 0.1s 리샘플
                                                    │
                              ┌─────────────────────┴──────────────────┐
                              │                                        │
                        autothresh                          HTML 안 JSON 임베드
                              │                                        │
                              └────────→ 초기 커트라인 ────────→ JS 후처리 ─→ 화면
```

캐시 경계는 선행 스펙 그대로다. 추론은 세션당 1회, 커트라인 탐색은 캐시된
곡선 위에서 브라우저가 즉시 처리한다.

## 5. 위험과 대응

### R1 — 후처리 구현이 파이썬과 JS로 갈라진다 (가장 큼)

`scores_to_segments`가 두 벌이 된다. 갈라지면 화면과 실제 계산이 달라지는데,
이건 알아채기 어려운 종류의 버그다. 비교 기준 자체가 거짓이 된다.

**대응:** 파이썬이 초기 커트라인에서 계산한 구간 목록을 HTML에 함께 싣는다.
페이지 로드 시 JS가 같은 파라미터로 계산해 대조하고, 불일치하면 페이지 상단에
빨간 배너로 경고한다. 조용히 틀리는 것만은 막는다.

비교 연산자는 선행 스펙과 동일하게 유지한다 — `score >= threshold`,
`gap <= merge_gap`, `duration >= min_duration`. 전부 등호 포함.

### R2 — 판단이 주관적이다

정답이 없으므로 "이 모델이 낫다"가 사람 인상에 의존한다. 재현되지 않고
남에게 설명하기 어렵다.

**대응:** 받아들인다. 이 도구의 목적은 **후보를 좁히는 것**이지 최종 수치를
내는 게 아니다. 상위 2~3개로 좁힌 뒤 정량이 필요하면 그 세션에 라벨을 찍어
기존 채점 리포트를 돌린다. 그래서 채점 경로를 남긴다.

### R3 — 긴 녹음의 추론 시간

47분 × 7모델을 CPU로 돌리면 오래 걸린다. 특히 AST는 10.24초 창을 2.5초 hop으로
밀어 ~4배 중복 연산을 한다.

**대응:** 캐시가 이미 막아준다(세션당 1회). `--detectors`로 일부만 돌릴 수 있고,
`[done]` 줄에 RTF가 찍히므로 첫 모델에서 총 소요를 가늠할 수 있다.

### R4 — 오디오와 점수 곡선의 시간축 어긋남

모델마다 hop이 다르다(PANNs 1.0s, YAMNet 0.48s, Silero 0.1s). 리샘플이 어긋나면
화면의 구간과 실제로 들리는 소리가 밀린다. 정답이 없으니 눈으로만 검증된다.

**대응:** 기존 `resample_scores`로 전부 0.1초 격자에 맞춘다(선행 스펙에서
테스트됨). HTML의 시간축은 오디오 `duration` 하나만 기준으로 삼고, 모든 행이
같은 축을 공유한다.

## 6. 테스트 전략

정답이 없는 도구라도 **기계적으로 검증 가능한 것**은 전부 테스트한다.

| 대상 | 검증 |
|---|---|
| `add-session` | yt-dlp를 모듈로 호출, 로컬 파일 변환, 중복 id 거부 |
| `_scene_ids` | 라벨 없는 wav도 잡힘, 라벨 있는 것과 공존 |
| `auto_threshold` | 이봉 분포에서 골짜기 반환, 단봉에서 0.5 폴백 + 근거 문자열, 이진 곡선 처리 |
| `cmd_report` | 라벨 없는 세션을 건너뛰고 죽지 않음 |
| explore HTML | 생성됨, 모델명 전부 포함, `<audio>` 태그, 점수 JSON 임베드, 파이썬 기준 구간 임베드 |
| CLI 출력 | cp949 인코딩 가능 (기존 회귀 테스트 확장) |

**JS 로직은 파이썬 테스트로 검증할 수 없다.** R1의 자체 대조 배너가 그 자리를
대신한다 — 테스트가 아니라 런타임 안전장치임을 명시한다.

---

## 7. 완료 기준

1. `bandpoc add-session <유튜브 URL>` 로 통짜 세션이 들어간다
2. `bandpoc add-session <로컬 파일>` 로 직접 녹음이 들어간다
3. `bandpoc run` 이 라벨 없는 세션의 점수를 캐시한다
4. `bandpoc explore` 가 오디오 재생 가능한 HTML을 만든다
5. 타임라인 클릭으로 해당 시점이 재생된다
6. 슬라이더 조작에 구간·Take 개수·목록이 즉시 반응한다
7. 모델별 커트라인이 자동으로 잡히고, 단봉 분포는 그 사실이 표시된다
8. 파이썬/JS 불일치 시 경고 배너가 뜬다
9. `bandpoc report` (기존 채점 경로)가 그대로 동작한다
10. 전체 테스트 통과

## 8. 범위 밖

- 브라우저에서 라벨을 찍는 기능 — 필요해지면 별도 스펙
- 모델 재학습·파인튜닝 — 이 프로젝트 전체의 범위 밖
- 세션 간 종합 순위 — 사람이 페이지를 보고 판단한다
- 합성 씬 경로 제거 — 그대로 유지한다
